## MyBatis 的缓存机制
1. `一级缓存`：SqlSession 内部生效

 **一级缓存默认开启，无需额外配置**

只要在**<font style="color:#DF2A3F;">同一个 sqlsession</font>** 中执行**相同的 sql 加相同的参数**，则第二次会**直接从缓存中获取数据**，不会访问数据库。缓存的生命周期与 sqlsession 绑定，sqlsession 关闭，则缓存会消失；执行 commit、rollback 或者**<font style="color:#DF2A3F;">增删改</font>**都会将缓存清除。

2. `二级缓存`：SqlSession 共享

二级缓存是**Mapper 级别的**，**同一个****<font style="color:#DF2A3F;">namespace下所有SqlSession</font>****共享同一份缓存**。

需要在 xml 中添加**<cache/>标签**才能开启，缓存生命周期和 sqlsessionFactory 一致，比一级缓存久。数据发生增删改时，namespace 缓存自动失效。开启二级缓存后，**先查询二级缓存，若二级缓冲未查询到，则查询一级缓存，也未查到则查询数据库**，查询到结果以后**<font style="color:#DF2A3F;">逐级回填缓存</font>**（先一级再二级）



## MyBatis 插件运行原理，以及如何编写一个插件？
1. `**原理**`： MyBatis插件机制**基于动态代理**实现，通过拦截** Executor（负责执行 SQL）、ParameterHandler（设置 SQL 参数）、ResultSetHandler（处理查询结果） 和 StatementHandler（处理 SQL 语句）** 四种核心对象的方法调用。在MyBatis 初始化时会加载配置的插件，形成 InterceptorChain拦截器链。当创建上述四大对象时，MyBatis 会判断是否存在匹配的拦截器，若存在则使用JDK 动态代理生成代理对象。方法被调用时，先触发 Plugin 的 invoke 方法，根据@Intercepts 和@Signature 注解判断是否需要拦截，如果匹配则执行插件的intercept方法，实现逻辑织入，从而实现功能增强。
2. `**编写**`：编写MyBatis插件需要三步
    1. 定义一个类实现Interceptor 接口
    2. 使用@Intercepts和@Signature 注解标明要拦截的对象类型、方法名和参数类型
    3. 在intercept方法中编写增强逻辑，并通过invocation.proceed()继续执行后续流程
    4. 重写 plugin方法返回代理对象(通常使用 Plugin.wrap)
    5. 在mybatis-config.xml中通过<plugins>配置该插件类及属性
3. `**应用场景**`：**SQL 性能监控**(记录执行时间)、**自动分页**(修改SQL添加limit)、**参数注入**(ParameterHandler 中添加公共参数)、**结果脱敏**(在ResultSetHandler 中处理敏感数据)、**SQL日志打印**(输出完整SQL)等。这些都可以通过拦截特定处理器并在intercept 中增强逻辑来实现。



## <font style="color:#DF2A3F;">MyBatis 的执行流程和核心思想</font>
1. **核心思想**：MyBatis 的核心思想是**通过映射文件(XML或注解)将SQL语句与Java对象进行绑定，并利用动态代理机制在运行时执行对应的SQL**。整个过程分为初始化阶段和执行阶段，**前者构建配置和映射关系，后者通过代理对象执行数据库操作**。
2. `**初始化阶段**`：1)解析全局配置文件 mybatis-config.xml；2)加载并解析所有Mapper XML文件；3)创建Configuration 对象，保存数据源、类型别名、插件、Mapper 注册等信息；4)将每个SQL 映射为MappedStatement 对象；5)注册Mapper 接口并关联MapperProxyFactory；6)最终构建SqlSessionFactory工厂对象
3. `**执行阶段**`：1）创建 SqlSession 会话；2）根据配置创建 Executor 执行器；3）通过动态代理生成Mapper 的代理对象；4）拦截接口方法，转换为 MapperMethod 执行；5）SQL 路由；6）将 java 参数转换为 JDBC 参数，设置到 preparedstatement；7）调用底层 JDBC 执行 sql；8）将 ResultSet 映射为 java 对象；9）维护一级缓存、二级缓存；10）提交事务，刷新缓存，关闭连接

## Mybatis 和 Hibernate 区别（优缺点）
1. `**Mybatis**` 是**半自动的 ORM 框架**，需要手动编写 SQL 语句，不同数据库之间有 sql 差异需要开发者自行处理，**可移植性较差**。但**更贴近 SQL，灵活性更高**。
2. `**Hibernate**` 是**全自动化 ORM 框架**，无需编写 SQL，由框架自动生成，**数据库可移植性较好**，能够**根据底层的数据库自动适配生成相应的 SQL，更加面向对象**。



## MyBatis 中#{}和${}的区别是什么？
#｛｝是 preparedStatement** ****<u><font style="color:#DF2A3F;">占位符 预编译处理</font></u>**，使用预编译机制，SQL 模板先被数据库解析和编译，参数**通过 set （）方法绑定**，不会改变原有 sql 结构，能够安全的设置参数，防止 sql 注入。**同时，他只能用于参数值的位置（固定）**

$｛｝是**<u><font style="color:#DF2A3F;">字符串拼接（字符串替换）</font></u>****，直接将参数拼接到 sql 中**，不进行预编译，会有依赖注入风险（拼接 or 1=1 恶意获取数据库信息）

## MyBatis 如何优化关联查询的性能
1. 优先使用嵌套结果映射而非嵌套查询以避免 N+1 （嵌套查询模式下，先执行一次主查询获取 N 条数据，之后对查询出来的数据进行关联查询，共执行 N+1 次）问题，解决 N+1 可以使用 MaBatis 延迟加载、使用嵌套结果映射。
2. 合理利用别名和字段投影减少冗余数据
3. 利用二级缓存缓存常用数据
4. 对频繁使用的关联查询建立合适的数据库索引

`**嵌套结果映射**`：**一次SQL进行JOIN查询并映射集合** （类似 left join）

`**嵌套查询**`：主查询获取主表数据，再通过 select 属性调用子查询获取集合数据（主查询+子查询）

## MyBatis 中的延迟加载
1. `概念`：允许在<font style="color:#DF2A3F;">需要访问关联数据时才触发</font>数据库查询，而不是在查询主对象时一次性加载所有关联数据，从而提升性能。（延迟加载的结果会放在缓存中，用于后续重复使用）
2. `原理`：**<font style="color:#DF2A3F;">通过动态代理实现</font>**。当启用延迟加载后，MyBatis 会为需要延迟的关联对象或集合创建代理对象。当真正需要访问这些对象时，代理才会**<font style="color:#DF2A3F;">拦截并触发 SQL 查询</font>**实际数据
3. `应用场景`：复杂关联关系场景，如一对一、一对多、多对多。典型场景：用户和地址信息、订单和订单列表，只有真正需要的时候才去查询关联数据，节省性能开销
4. `resultMap 中配置集合的延迟加载`：<colletion> 或 <association>标签中使用 fecthType= “lazy”，配合 select 属性指定延迟加载的查询语句。例如:`<collection property="orders" ofType="Order" select="selectOrdersByUserld" column="user_id" fetchType= "lazy"/>`

## 什么是 MyBatis-plus？
myBatisPlus 是 myBatis 的增强工具包，在 myBatis 的基础上增强了许多功能，比如提供一系列的 API 方法和代码生成器，可以生成开发中重复的 CRUD 操作，使开发者无需手动编写 SQL 语句，就能完成常见的数据库操作。同时还有一系列工具：条件生成器（用于构造复杂查询）、内置分页插件、代码生成器可以自动生成实体类、Mapper 接口文件和映射文件，减少开发中的重复操作。

## MyBatis 中实现一对一、一对多关联查询
1. `一对一`：MyBatis中通过resultMap 配合**<font style="color:#DF2A3F;"><association></font>**标签实现一对一关联查询。可以使用嵌套结果映射(一次SQL联表查询)或嵌套查询(多个SQL语句，主查询+子查询)。在嵌套结果中，用<association>映射关联对象的属性;在嵌套查询中，通过 select 属性指定另一个查询语句来加载关联数据。
2. `一对多`：MyBatis中通过 resultMap配合**<font style="color:#DF2A3F;"><collection></font>**标签实现一对多关联查询。适用于一个实体对应多个子实体的情况，如用户与订单。可以采用嵌套结果映射(一次SQL进行JOIN查询并映射集合)或嵌套查询(主查询获取主表数据，再通过 select 属性调用子查询获取集合数据)，其中ofType 指定集合元素类型。



## Mybatis 中的执行器
1. `SimpleExecutor` 简单执行器：**每次执行 SQL 都会创建新的 statement**，执行完毕以后**直接关闭**，不会进行复用。适用于单次简单操作，无 statement 缓存，但频繁操作相同 SQL 性能较低。
2. `ReuseExecutor` 重用执行器：通过 SQL 作为键，**缓存已存在的 statement**，执行相同的 SQL 时直接**复用**，避免重复创建和销毁 statement，减少数据库交互开销，适合频繁执行相同 SQL 场景。
3. `BatchExecutor` 批量执行器：利用 **JDBC 的批处理机制**，将多个相同的更新操作（**增删改，不使用 SELECT**）通过 addBatch 方法添加到批处理队列中，最后统一执行 executeBatch，显著提高批量数据库操作性能。（**<font style="color:#DF2A3F;">一般在事务提交或手动刷新触发批量提交</font>**）
