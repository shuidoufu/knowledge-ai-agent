## 什么是 SpringBoot？
Spring Boot是**基于 Spring框架的扩展**，它并不是替代 Spring，而是**通过自动化配置和默认配置简化了 Spring应用的搭建和开发过程**。可以说，Spring Boot =Spring +自动配置+起步依赖+内嵌服务器，目的是让 Spring 开发更简单高效。

`**核心特点**`：Spring Boot 的核心特性主要包括五点：

1. **自动配置**，根据引入的依赖自动配置Bean，基于@EnableAutoConfiguration和 spring.factories实现
2. **Starters依赖启动器**，提供场景化依赖套餐，如 spring-boot-starter-web，解决版本冲突问题
3. **内嵌容器**，将Tomcat、Jetty等嵌入jar 包中，实现java -jar 直接运行
4. **外部化配置**，支持application.yml等多环境配置文件，并可通过命令行或环境变量动态调整
5. **Actuator**，提供健康检查、监控指标等生产级监控端点。这些特性共同实现了开箱即用、简化开发与部署的目标。



## SpringBoot 的启动流程？
`**启动流程**`： Spring Boot启动从SpringApplication.run()开始，主要经历：

① 构造SpringApplication，推断应用类型（Web/Reactive/None）加载初始化器，获取 application 监听器

② run 方法启动，启动计时器、配置 handless 模式、发布启动事件

③ 准备Environment，加载配置文件、系统环境变量、命令行参数

④ 根据应用类型创建上下文 ApplicationContext

⑤ 刷新Context（加载Bean、实例化单例Bean、启动内嵌服务器）

⑥ 执行Runner完成启动。

`**核心步骤**`：SpringBoot 启动流程核心分为两大部分:

1. 创建SpringApplication实例，进行初始化配置;
2. 执行run方法，完成环境准备、容器创建、刷新上下文、启动内嵌服务器和执行启动后任务等。



## Spring、SpringMVC、SpringBoot区别
	`**spring和springMvc**`**: **

	1. spring是一个一 站式的轻量级的java开发框架,核心是控制反转(IOC) 和面向切面(AOP)， 针对于开发的

	WEB层(springMvc)、业务层(Ioc)、 持久层(jdbcTemplate)等都提供 了多种配置解决方案;

	2. springMvc是spring基础之上的一个MVC框架,主要处理web开发的路径映射和视图渲染,属于spring框架中WEB层开发的一部分;

	`**springMvc和springBoot**`**: **

	1、springMvc属于一 个企业WEB开发的MVC框架， 涵盖面包括前端视图开发、文件配置、后台接口逻辑开发等，XML、config等配置相对比较繁琐复杂;

	2、springBoot框架相对于springMvc框架来说， 更专注于开发微服务后台接口，不开发前端视图，同时遵循默认优于配置,简化了插件配置流程,不需要配置xml,相对springmvc, 大大简化了配置流程;

	

	`**总结**`**:**

	1、Spring 框架就像一个家族，有众多衍生产品例如boot、security. jpa等等。但他们的基础都是Spring的

	ioc、aop等. ioc提供了依赖注入的容器，aop解决 了面向横切面编程，然后在此两者的基础上实现了其他延伸产品的高级功能;

	2、springMvc主要解决WEB开发的问题， 是基于Servlet的一个MVC框架，通过XML配置，统一开发前端视图和后端逻辑; 



## Spring Boot 的监听器机制是如何工作的?有哪些关键事件?
Spring Boot 使用事件驱动模型，通过 SpringApplicationRunListeners触发多个生命周期事件，如 ApplicationStartingEvent(启动开始)、ApplicationEnvironmentPreparedEvent(环境准备)、ApplicationStartedEvent(上下文启动)、ApplicationReadyEvent(应用就绪)等，供监听器响应处理。



## SpringBoot 如何通过 main 方法启动 web 项目？
通过 main 方法调用 SpringApplication.run （**返回已配置并刷新的应用上下文对象** **<u>configurableApplicationContext</u>**）启动应用。该**<font style="color:#DF2A3F;">方法会创建 Spring 应用上下文，准备环境、加载自动配置类，刷新上下文，触发内嵌的 Web 服务器的创建和启动</font>**。最终由ServletWebServerApplicationContext 负责启动内嵌服务器并处理 HTTP 请求。



## SpringBoot 中的 @SpringBootApplication 注解有哪些组成？
1. @SpringBootConfiguration：标识配置
2. ‌@EnableAutoConfiguration：启动自动配置。它会从 spring.factories 文件中加载预定义的自动配置类，**根据****<u>类路劲依赖</u>****自动配置相应的组件**，比如自动配置内置的 WEB 服务器。
3. CompentScan：开启组件扫描



## @Conditional 注解的核心作用？常见的条件注解有哪些？
1. `**@Conditional**` 注解是条件化配置的基础，**他可以根据特定的条件**（如类存在、Bean 不存在、配置属性等）**来决定是否创建某个 Bean 或加载某个类**。是实现自动配置灵活控制的关键。
2. `**@ConditionOnClass**`：当类路劲存在指定类时生效
3. `**@ConditionalOnMissingBean**`：当容器中不存在指定 bean 时生效
4. `**@ConditionalOnProperty**`：当配置文件中存在指定属性时生效

**它们，用于控制自动配置类和 Bean 的加载条件**

## 如何SpringBoot中定义和读取自定义配置？
1. 定义：在配置文件中定义所需要的配置信息
2. 读取配置：
    1. 使用**<font style="color:#DF2A3F;">@Value</font>**注解（简单属性）： @Value("${myapp.name}")
    2. **<font style="color:#DF2A3F;">@ConfigurationProperties</font>** （**<font style="background-color:#FBDE28;">配置的属性要放到指定的配置文件中：</font>****<font style="color:#DF2A3F;background-color:#FBDE28;">application.yml</font>**）配置类，结合@EnableConfigurationProperties 启用自定义配置属性类

```java
@Data  // Lombok
@Component
@ConfigurationProperties(prefix = "myapp")
public class MyAppProperties {
    
    private String name;
    private String version;
    private List<String> features;
    private DatabaseProperties database;
    
    @Data
    public static class DatabaseProperties {
        private String url;
        private String username;
        private int timeout;
    }
}

@EnableConfigurationProperties(MyAppProperties.class)  // 如果不用@Component
```

    3. 使用 **<font style="color:#DF2A3F;">@PropertySource</font>** 加载自定义文件（**<font style="background-color:#FBDE28;">通过这种防止，可以读取指定配置文件中的属性</font>**）

```java
@Configuration
@PropertySource("classpath:custom.properties") // custom.properties 用户自定义属性配置文件
public class CustomConfig {
    
    @Value("${custom.key}")
    private String customKey;
}
```

## SpringBoot 打成的 jar 和普通的 jar 有什么区别？
SpringBoot 打成的 jar 包可以使用 java -jar 命令直接运行，包含了源码、依赖库、配置文件和内嵌的服务器。

普通 jar 包，只包含编译完成后的类文件和资源，不具备独立运行能力，需要配合外部容器和 JVM 环境来运行。



## SpringBoot 中如何处理跨域请求（cors）？
跨域：‌**跨域问题是指浏览器由于****<font style="color:#DF2A3F;">同源策略</font>****的安全限制，阻止从一个源（如A网站）向另一个不同源（如B网站）发起请求或获取数据的技术问题**‌<font style="color:rgb(51, 51, 51);">。它本质上是浏览器为保护用户安全而实施的一种机制，并非服务器限制。‌‌</font>

1. 使用**<font style="color:#DF2A3F;">@CrossOrigin 注解</font>**实现局部跨域配置。用于 controller 或者方法上，可以指定允许的源、HTTP 方法、请求头等。
2. 实现 **<font style="color:#DF2A3F;">WebMvcConfigurer 接口，重写 addCorsMappings 方法</font>**进行全局跨域配置。在该方法中使用 CorsRegistry 添加映射路径并设置 allowedOrigins.allowedMethods等参数，从而实现对整个应用的统一跨域配置。	
3. 添加 **<font style="color:#DF2A3F;">CorsFilter 过滤器</font>**来处理跨域请求



## SpringBoot 中如何实现一个拦截器？
在Spring Boot中实现拦截器需要创建一个类**实现HandlerInterceptor接口，并重写preHandle、postHandle和afterCompletion方法**。然后通过配置类实现WebMvcConfigurer接口，在**<u>addInterceptors方法中注册该拦截器并指定拦截路径</u>**。

`**preHandle**`在请求到达控制器之前执行，可用于**权限校验（获取请求头中 token，验证有效性，来判断同意请求或者终止请求）;**

`**postHandle**`在控制器处理完请求后、视图渲染前执行，可用于修改响应内容;

`**afterCompletion**`在视图渲染完成后执行，通常用于资源清理。

**拦截器可以拦截静态资源**：默认情况下如果拦截路径配置为/**，会拦截包括静态资源在内的所有请求。可以通过**addPathPatterns添加需要拦截的路径**，同时使用**excludePathPatterns排除静态资源路径**如/css/**、/js/**等来避免不必要的拦截。



## <font style="color:#DF2A3F;">拦截器和过滤器（Filter）有什么区别</font>？
Filter是**Servlet规范的一部分，****<u><font style="color:#DF2A3F;">执行优先级高</font></u>****，作用于所有HTTP请求**;

Interceptor**是Spring MVC组件，仅对SpringMVC处理的请求生效**。

Filter在更前端执行，常用于**编码、CORS 等****<u>全局处理</u>**，而Interceptor更适合业务相关的**权限、日志**等操作

## SpringBoot（Spring）中为什么不推荐使用@Autowired？
1. <u>可能导致空指针异常</u>（**<font style="color:#DF2A3F;">如在构造器方法中使用未注入的依赖，字段注入依赖晚于构造函数执行，所以构造函数执行的时候，字段还未注入，导致空指针</font>**）
2. <u>与 Spring 容器强耦合</u>导致**<font style="color:#DF2A3F;">单元测试困难</font>**（脱离容器的纯单元测试无法直接实例化对象并注入模拟依赖，需要启动 Spring 上下文）
3. <u><font style="background-color:#FBDE28;">会掩盖循环依赖问题</font></u>，且容易导致类违反单一职责原则。



**推荐使用构造器注入**：构造器注入能够确保强制依赖注入（对象创建时所有依赖必须提供），支持不可变性（依赖一旦注入，不可更改）、更易于单元测试（可直接传入 mock 对象）、并且能通过臃肿的构造函数提醒开发者类可能职责过多。

## SpringBoot 工程启动后，如何将数据库中的固定数据加载到 Redis 缓存中？
可以在 Spring Boot 应用启动完成后，**<font style="color:#DF2A3F;">通过实现</font>****<u><font style="color:#DF2A3F;">CommandLineRunner 或 ApplicationRunner </font></u>****<font style="color:#DF2A3F;">接口</font>**<font style="color:#DF2A3F;">，</font>**<font style="color:#DF2A3F;">在run 方法中从数据库查询数据并存入 Redis</font>**。另外，也可以使用**<u><font style="color:#DF2A3F;">@PostConstruct 注解</font></u>**标记初始化方法，在Bean 初始化后执行数据预热逻辑。

```java
@Component
public class CacheWarmUpRunner implements CommandLineRunner {
    @Autowired
    private ProductRepository productRepository;
    @Autowired
    private StringRedisTemplate redisTemplate;

    @Override
    public void run(String... args) {
        // 查出所有热门商品，一次性灌入缓存
        List<Product> hotProducts = productRepository.findHotProducts();
        for (Product p : hotProducts) {
            redisTemplate.opsForValue().set("product:" + p.getId(), JSON.toJSONString(p), 30, TimeUnit.MINUTES);
        }
    }
}
```

```java
// 该注解标记的方法会在当前Bean依赖注入完成后立即执行。适合某个特定服务自己负责预热自己那部分缓存的场景。
@Service
public class AreaCacheService {
    @Autowired
    private AreaRepository areaRepository;
    @Autowired
    private StringRedisTemplate redisTemplate;

    @PostConstruct
    public void warmUpAreaCache() {
        List<Area> areas = areaRepository.findAll();
        redisTemplate.opsForValue().set("all_areas", JSON.toJSONString(areas));
    }
}
```

```java
// 这是最稳妥的方案。ApplicationReadyEvent 在应用完全就绪、可以接收请求时才触发,
//比CommandLineRunner 还要晚一点。如果你的缓存预热逻辑特别重要，不能有任何闪失，用这个最保险。
@Component
public class CacheWarmUpListener {
    @EventListener(ApplicationReadyEvent.class)

        // 应用完全就绪后执行缓存预热
    }
}
```
