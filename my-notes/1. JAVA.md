##  Java 中有哪些集合？
集合框架主要为：**Collection 和 Map**，Collection 存储单个元素，Map 存储键值对

Collection 又有三个分类：

1. List：**有序可重复**，通过下标访问元素。**<font style="color:#DF2A3F;">ArrayList 底层是数组，查询快，增删慢；LinkedList 底层是双向链表，增删快查询慢</font>**；Vector 是线程安全的动态数组，开销大，很少使用
2. Set：**不允许重复元素**。**<font style="color:#DF2A3F;">HashSet 基于哈希表，元素无序；LinkedHashSet 用链表维护插入顺序；TreeSet 基于红黑树，元素按大小排序，有序</font>**。
3. Queue：队列，先进先出。PriorityQueue 优先级队列，按元素大小出队；LinkedList，实现了 Queue 接口

Map 分为五类：

1. HashMap：最常用，基于 Hash 表，键值对无序，key 不可重复，允许 null 键值
2. LinkedHashMap：维护插入顺序，编历时按放入顺序输出
3. TreeMap：基于红黑树，按 key 大小排序
4. ~~Hashtable：旧的线程安全 Map，不允许 null，锁颗粒度大，被ConcurrentHashMap替代~~
5. ConcurrentHashMap：**线程安全的 Map，用于高并发场景，****<u><font style="color:#DF2A3F;">分段锁设计</font></u>**



**ArrayList 和 LinkedList 如何选择？**

多数情况使用 ArrayList。ArrayList 查询速度很快，增删底层做了优化，移动元素使用 System.array.copy，拷贝起来比想象中要快，同时是缓存友好型的，ArrayList 在大多数场景下都更快。LinkedList 适合当队列，频繁操作头部。

**ConcurrentHashMap 和 Hashtable 都是线程安全的，有什么区别?**

**锁的颗粒度不同**，Hashtable 是整个表的一把大锁，同一时刻只有一个线程能够操作。ConcurrentHashMap 使用 synchronized+CAS，锁的颗粒度细到单个桶，并发度更高。他俩都**<font style="color:#DF2A3F;">不允许 null 键值</font>**，但是 HashMap 可以使用 null 键值。



## Java 中的 HashMap 原理
HashMap 底层数据结构：**<font style="color:#DF2A3F;">数组+链表+红黑树解决冲突（JAVA8 引入）</font>**

1. `数据存储`：存储 key - value 时，先使用 hash 算法计算 key 的 hashCode，然后用（n-1) * hash 计算出元素放入数组的下标位置。
2. `哈希冲突`：两个不同的 key 计算出的下标相同。HashMap 使用链表将他们串起来，jkd8 做了优化，**如果同一个下标下的链表超过 8 个节点，会自动转换为红黑树，查找速度从 O（n）变成 O（logn）**
3. `扩容机制`：数组长度优先，HashMap 的负**<font style="color:#DF2A3F;">载因子默认为 0.75，数组超过 75%会自动扩容，将数组大小翻倍</font>**，然后所有数据重新计算位置放到新的数组中（这个操作为 refresh）。



**红黑树转换阈值****<font style="color:#DF2A3F;">：链表长度超过 8 且数组长度大于等于 64 时转换，链表节点小于 6 时候退化为链表</font>**（6 和 8 用作缓冲区间，避免在临界点反复转换）

**默认容量和负载因子**：**<font style="color:#DF2A3F;">默认容量 16，负载因子 0.75</font>**。负载因子过高，内存占用少但冲突多；过低，冲突少但浪费内存。提前设定好初始容量，容量计算方式：比如要存储 100 个元素，**<font style="color:#DF2A3F;">（int）（100 / 0.75f）+1</font>**<font style="color:#DF2A3F;"> </font>能避免扩容。

**hashCode 和 equals 的重要性**：HashMap 的 key 必须正确实现 hashCode()和 equals()方法。**<font style="color:#DF2A3F;">hashCode()决定 </font>****<u><font style="color:#DF2A3F;">key</font></u>****<font style="color:#DF2A3F;"> 存储的位置，equals()决定两个</font>****<u><font style="color:#DF2A3F;">key</font></u>****<font style="color:#DF2A3F;">是不是同一个</font>**。put 的时候，如果两个 key 的 hashCode()相同但 equals()返回false，它们会被当成不同的 key 存在同一个桶的不同位置。如果 hashCode()实现得不好导致分布不均，或者equals()写错了，会导致元素找不到或者重复插入。



**HashMap 线程不安全**：<u>因为其内部没有同步控制</u>。在多线程环境下，如果多个线程同时执行put 操作并触发扩容，JDK1.7中可能因头插法导致链表成环，从而引发死循环;即使在1.8中虽然改成了尾插法，<u>但仍存在数据覆盖</u>等问题。因此多线程场景应使用ConcurrentHashMap。（**<font style="color:#DF2A3F;">没有同步机制，多线程并发场景下会导致数据覆盖问题</font>**）

## 接口的默认方法和抽象类有什么区别？什么时候用接口？什么时候用抽象类？
`**区别**`：

    1. 接口不能有构造方法，抽象类可以有构造方法；
    2. 接口默认字段是 public static final，抽象类可以有普通方法；
    3. 一个类可以实现多个接口，但只能继承一个抽象类

`**选择**`：

    1. **定义一种能力或行为**，用接口，比如 Comparable、Serializable；
    2. **如果定义一类事物的共性，有状态需要维护**用抽象类，如 AbstractList、AbstractMap
    3. Java8 之后接口能力增强，优先使用接口，除非需要共享状态或构造逻辑

## Lambada 表达式和匿名内部类有什么区别？
主要有3 点区别。

第一，L**ambda 只能实现函数式接口**,匿名内部类可以实现任意接口或继承类。

第二，匿名内部类**每次都会生成**一个新的class文件，Lambda 用 invokedynamic 指令动态生成，**不会产生额外**的 class 文件。

第三，**匿名内部类的 this 指向自身，Lambda 的 this 指向外部类**。**性能上，Lambda首次调用会稍慢**，因为要做 invokedynamic的链接，但后续调用和匿名内部类差不多，甚至更快一点，因为JVM可以做更多优化。



## Java 的 Optional 类是什么？以及应用场景？
`**概念**`： Optional是Java8引入的一个容器类，用于减少空指针异常风险，提高代码可读性和表达性。它本质上是一个可以容纳T类型对象的包装类，用来替代直接使用null 来表达'无值'的情况，从而更清晰地处理可能为空的结果（**<font style="color:#DF2A3F;">最好用在方法的返回值上</font>**）。

**创建方式**：

1. `Optional.of(value)`包装非空值，传 null 直接抛NullPointerException
2. `Optional.ofNullable(value)`包装可能为空的值，传 null 返回空 Optional
3. `Optional.empty()`创建一个空的Optional

**取值**：

```java
Optional<String> opt = Optional.ofNullable(getValue());

// 直接取，空了抛 NoSuchElementException（不推荐）
opt.get();

// 空了返回默认值
opt.orElse("default");

// 空了调用 Supplier 生成默认值（只有option空才会执行）
opt.orElseGet(() -> createDefault());

// 空了抛自定义异常
opt.orElseThrow(() -> new BusinessException("not found"));

```

**map()和flatMap()在Optional 中有何不同?**

`map()`用于对Optional中的值进行转换，**返回一个新的**Optional包装转换后的结果;如果原Optional为空，则不执行map中的函数。

`flatMap()`也用于转换，但它**要求函数返回的是Optional类型**，避免出现Optional<Optional<T>>的嵌套结构，常用于**链式调用**多个可能返回Optional的方法。



## AQS
AQS(AbstractQueuedSynchronizer)是Java中用于**构建锁和同步器**的基础框架，它通过维护一个**volatile** 的 state 状态和一个**FIFO的双向同步队列**，来管理线程对共享资源的并发访问,

`**核心**`：

1. **state 同步状态**，用volatile修饰，表示资源的当前状态；通过CAS操作修改。在ReentrantLock中表示重入次数，在 Semaphore中表示可用许可数，子类通过getState()、setState()和compareAndSetState()来控制其值。
2. **同步队列**，是一个变体的**CLH双向链表**，用于存放等待获取资源的线程。每个节点包含线程引用、等待状态、前继和后继指针。
3. **独占与共享**两种模式，分别支持单一或多个线程同时获取资源。



## Java 中如何创建多线程？
常见的创建多线程的方式有五种:

1. 实现Runnable接口：没有返回值、不能抛出异常检测
2. 继承Thread类
3. 使用Callable 和FutureTask：Callable 的 call 方法有返回值，允许抛出检查异常；可以使用**<font style="color:#DF2A3F;">Callable接口结合FutureTask来获取线程执行结果</font>**。先**<font style="color:#DF2A3F;">创建Callable实现类并重写call()方法</font>**返回结果，再将其**<font style="color:#DF2A3F;">包装为FutureTask对象</font>**，传给Thread 构造函数并启动线程，最后通过**<font style="color:#DF2A3F;">FutureTask.get()</font>**方法获取执行结果。
4. 使用线程池(ExecutorService）：线程池可以管理和复用线程、控制并发数量，减少资源开销，适合处理大量并发任务。
5. 使用CompletableFuture：Java 8引入的异步编程工具，**默认使用ForkJoinPool线程池（线程数通常为 CPU 核心数）**。可以通过 **<font style="color:#DF2A3F;">runAsync()执行无返回值任务</font>**，**<font style="color:#DF2A3F;">supplyAsync()执行有返回值任务</font>**，并通过**<font style="color:#DF2A3F;">thenApply、thenAccept等方法链式处理多个异步任务之间的依赖关系</font>**，极大简化了异步编程复杂度。

其中，前两种适用于简单场景，**后三种更适用于需要返回值、管理并发或处理异步依赖的场景**。



## 数组和链表在 Java 中的区别是什么？
**数组（O（1），连续的，直接通过下标访问）**基于连续的内存块，大小固定，需要预先分配空间，**插入删除时可能需要重新分配内存**，而**链表（O（n），不连续，要从头遍历链表，直至找到元素）**由节点组成，内存中不需要连续存储，每个节点通过指针链接下一个节点，可以动态扩展和收缩，适合频繁修改大小的场景



## 什么是 Java 中的原子性、可见性和有序性？
Java 并发编程的三大核心特性：原子性、可见性、有序性。

`**原子性**`：一**个操作要么全部执行完毕，要么完全没执行**，中间不会被其他线程打断

`**可见性**`：**一个线程修改了共享变量，其他线程可以立即看到共享变量的最新值**。CPU 有自己的高速缓存，线程修改的值可能还在缓存没有刷回主内存，别的线程就读到了旧值。

`**有序性**`：指**程序执行顺序和代码写的顺序一致**。编译器和CPU 为了性能会对指令做重排序，单线程下没问题，多线程就可能出现诡异的bug。

## 如何实现 Java 中的原子性？
Java中可以通过**synchronized关键字、Lock接口(**如ReentrantLock)以及java.util.concurrent.atomic包下的原子类(如AtomicInteger、AtomicLong)来实现原子性。原子类底层通常基于**CAS(Compare-And-Swap**)指令实现，避免了锁带来的性能开销。

**CAS**：是**一种硬件级别的原子操作**，它**比较内存中某个位置的当前值与预期旧值**，如果相等，则将该位置更新为新值。这个过程是原子的，不可分割。

CAS需要三个操作数:**变量的内存地址**、**旧的预期值**、**新值**。CPU根据内存地址拿到当前值，和预期值比较，相等就替换成新值，不相等就返回失败。失败了一般会自旋重试，直到成功为止。



## 如何保证 Java 中的可见性？
可以使用volatile关键字、synchronized关键字或Lock机制来保证可见性。

**volatile变量的****<u>写操作会强制刷新到主内存</u>****，读操作会从主内存重新加载;**

synchronized在进入和退出时**也会同步主内存与工作内存的数据**，从而保证变量的可见性。



## 什么是 Java 的内存模型（JMM）？
`**概念**`： Java 内存模型(JMM)是JVM定义的一种规范，用于控制多线程环境下**变量在主内存和线程本地内存之间的交互规则**。它确保了**<font style="color:#DF2A3F;">并发编程中</font>**的可见性、有序性和原子性，屏蔽了底层硬件差异，使开发者可以通过 synchronized、volatile等关键字编写线程安全的代码。	

+ 主内存：所有线程共享的区域，存储变量的原始数据;
+ 本地内存：本地内存是线程私有的抽象概念，实际对应CPU寄存器、高速缓存等。线程不能直接操作主内存，需将变量拷贝到本地内存进行读写，再刷新回主内存。

`**三大特性**`：JMM的三大特性是:**可见性**(一个线程修改变量后其他线程能立即看到)、**有序性**(防止指令重排序带来的问题)、**原子性**(操作不可中断)、有序性。这些特性通过volatile、synchronized等机制来保证,

`**使用 JMM 理由**`：因为Java是跨平台语言，不同操作系统和硬件的内存访问机制存在差异。JMM **提供了一套统一的抽象规范，屏蔽底层CPU缓存、寄存器、内存屏障等细节**，让开发者无需关心平台差异，只需遵循 JMM规则即可写出正确的并发程序。



## JVM 概念？
JVM是一个虚拟的计算机，它提供了一套完整的硬件抽象，包括指令集、寄存器、堆栈和垃圾回收机制，能够在不同操作系统上模拟统一的运行环境，使Java程序无需修改即可运行。



## JVM 由哪些部分组成？ 	
JVM 主要由四部分组成：JVM 主要由四个部分组成:**类加载器子系统(ClassLoader)、运行时数据区(Runtime Data Area)、执行引擎(Execution Engine)，以及本地方法接口(Native Interface，简称 JNl)。**

java 的运行： 

1. 首先通过**类加载器**（ClassLoader）会**<font style="color:#DF2A3F;">把 Java 代码转换成字节码</font>**
2. **运行时数据区**（Runtime Data Area）**<font style="color:#DF2A3F;">再把字节码加载到内存中</font>**，而字节码文件只是 JVM 的一套指令集规范，并不能直接交给底层操作系统去执行，
3. 因此需要特定的命令解析器**执行引擎**（Execution Engine），**<font style="color:#DF2A3F;">将字节码翻译成底层系统指令</font>**，再交由 CPU 去执行，
4. 而这个过程中如果需要调用其他语言的外部代码，需要**本地库接口**（Native Interface）来实现整个程序的。



`**类加载器的执行过程**`：

1. **加载**：根据查找路径找到相应的 class 文件然后导入；
2. **检查**：检查加载的 class 文件的正确性；
3. **准备**：给类中的静态变量分配内存空间；
4. **解析**：虚拟机将常量池中的符号引用替换成直接引用的过程。符号引用就理解为一个标示，而在直接引用直接指向内存中的地址；
5. **初始化**：对静态变量和静态代码块执行初始化工作。



`**运行时数据区**`：

运行时数据区是JVM内存管理的核心，按照线程是否共享分两类:

**线程私有的区域：**

1. 程序计数器，记录当前线程执行到哪条字节码指令了，是唯一不会OOM的区域
2. 虚拟机栈，每个方法调用会压一个栈帧进去，存局部变量表、操作数栈、方法出口这些信息
3. 本地方法栈，跟虚拟机栈差不多，专门给native方法用的

**线程共享的区域：**

1. 堆，对象实例基本都在这儿分配，也是GC的主战场，按分代模型分年轻代和老年代（<u><font style="color:#DF2A3F;">对象实例和数组</font></u>）
2. 方法区，存类的<u><font style="color:#DF2A3F;">元数据、常量池、静态变量</font></u>。JDK8之前叫永久代，8之后改成Metaspace，直接用本地内存



`**执行引擎**`

执行引擎负责把字节码转换为机器指令并执行，内部有两个核心组件配合工作:

**解释器**负责逐条解释字节码并执行，启动速度快但效率一般。JIT **编译器**会把执行次数超过阈值的热点代码编译成本地机器码缓存起来，下次直接执行机器码，性能提升明显。

HotSpot 里有两个IT 编译器:C1 编译器做轻量级优化，编译快;C2编译器做深度优化，编译慢但生成的代码跑得快。JDK8 默认用分层编译，先让C1 快速编译，热点代码再让C2深度优化。



`**本地方法接口**`

JNI允许Java程序调用C/C++这类本地代码，也能让本地代码回调Java。典型场景是访问操作系统级别的功能，比如文件操作底层、网络 socket底层，或者调用高性能的图形库、加密库。

声明一个 native 方法后，用 javah 生成头文件，再用 C/C+ +实现对应函数，编译成动态链接库，Java 里 System.loadLibrary 加载进来就能调了。



## JVM 的内存区域是如何划分的？
JVM运行时数据区分成五块:**<font style="color:#DF2A3F;">堆、方法区、虚拟机栈、本地方法栈、程序计数器</font>**。其中堆和方法区是所有线程共享的，另外三个是每个线程私有的。

（1）堆是最大的一块内存，所有new出来的对象和数组都往这儿放。GC主要就在堆上干活，新生代老年代那套都在这里面。

（2）方法区存的是类的元信息，包括类结构、常量池、静态变量、IT编译后的代码缓存。JDK8之前用永久代实现，容易撑爆内存，JDK8换成了元空间，直接用系统内存，上限高多了。

（3）虚拟机栈是线程私有的，每调用一个方法就压一个栈帧进去，方法执行完就弹出来。栈帧里装着局部变量表、操作数栈、动态链接、方法返回地址这些东西。

（4）本地方法栈跟虚拟机栈差不多，区别是它服务的是native方法，也就是用C/C++写的那些JN代码。

（5）程序计数器就是个小本本，记录当前线程执行到哪条字节码指令了。线程切换回来得知道从哪继续跑。这是唯一不会OOM的区域，因为它就存一个地址，几个字节的事。

## 编译执行和解释执行的区别是什么?JVM 使用哪种方式？
1. **编译执行**是在程序**<font style="color:#DF2A3F;">运行前</font>**通过编译器将源代码**<font style="color:#DF2A3F;">一次性</font>**编译为机器码，运行时直接执行机器码，因此**运行速度快**，但需针对不同平台分别编译，跨平台性差。

**解释执行**是在**<font style="color:#DF2A3F;">运行时</font>**通过解释器**<font style="color:#DF2A3F;">逐行翻译</font>**源代码并执行，无需预先编译，**跨平台性好**，但每次执行都需要翻译，运行速度较慢。

2. **JVM同时使用了编译执行和解释执行**。它首先通过<font style="color:#DF2A3F;">解释器</font><u><font style="color:#DF2A3F;">逐行解释</font></u><font style="color:#DF2A3F;">执行</font><u><font style="color:#DF2A3F;">字节码</font></u>，提升启动速度和跨平台性;同时引入即时编译器(JIT)，将<font style="color:#DF2A3F;">频繁执行的热点代码编译为</font><u><font style="color:#DF2A3F;">本地机器码</font></u>，以提高运行效率。因此，JVM是混合执行模式。

## Java 中什么情况会导致死锁？如何避免？
死锁主要是两个或多个线程之间互相持有对方需要的锁，互相都不释放，从而导致死锁。发生死锁的四个必要条件（同时具备）：

+ **互斥**:资源同一时刻只能被一个线程占用
+ **持有并等待**:线程拿着一个锁的同时，还想要另一个锁
+ **不可剥夺**:线程拿到的锁不能被强行抢走
+ **循环等待**:线程之间形成环形的锁依赖链



避免/降低死锁的常用方法（打破任意条件即可）（**锁能不使用就不使用**）

+ **固定加锁顺序**：所有线程按照顺序获取锁，不会形成环路
+ **使用 trylock 超时机制**：ReentrantLock 的**<font style="color:#DF2A3F;"> tryLock（timeout）</font>**尝试获取锁，超时就放弃，避免无限等待
+ **缩小锁的颗粒度**：锁的范围越小，持有时间越短，发生死锁概率越低
+ **避免嵌套锁**：能用一把锁搞定就不要两把，嵌套越深，死锁概率越大



## <font style="color:#DF2A3F;">Java 线程池原理</font>
1. 线程池是一种池化技术，核心思想就是**复用线程**，避免每来一个任务就 new 一个Thread。创建销毁线程的开销不小，一个线程起码占用1MB 左右的栈空间，还有操作系统层面的调度成本。

线程池有几个关键参数:**核心线程数、最大线程数、空闲存活时间、工作队列、拒绝策略、线程工厂、时间单位**

`**工作流程**`：

1)任务来了先看核心线程够不够用，不够就创建新线程处理。默认核心线程是懒创建的，有任务才new，不过可以通过 prestartAlICoreThreads预热。

2)核心线程数满了之后，新任务不会立刻创建线程，而是先丢到工作队列里排队。

3)队列也塞满了，这时候才会创建非核心线程，最多创建到最大线程数。

4)队列满了、线程也到顶了，再来任务就触发拒绝策略。

5)线程空闲超过 keepAliveTime，并且当前线程数超过核心线程数，多余的线程会被回收。设置 allowCoreThreadTimeOut 为 true 的话连核心线程也能回收。

## 如何合理的设置 Java 线程池的线程数？
设置线程池线程数需根据任务类型来决定。主要分为CPU密集型和I/O密集型任务。

**CPU密集型**任务应尽量减少线程上下文切换，推荐设置线程数为**CPU核心数+1**。

**I/O密集型**任务由于线程常因等待I/O被阻塞，同时**<font style="color:#DF2A3F;">IO操作并不占用CPU</font>**，因此<font style="color:#DF2A3F;">可设置更多线程以</font>提高CPU利用率，通常建议为**CPU核心数*2或更多**。但这些仅为理论参考值，实际生产中需结合硬件配置、预期CPU利用率和负载情况，通过压测不断调优得出最优参数。

## <font style="color:#DF2A3F;">Java 中的序列化和反序列化是什么？（java 对象不能持久化和传输，必须转换为二进制字节流）</font>
1. **序列化**：将内存中的 Java 对象转换成二进制字节流，**<u>以便将其保存到磁盘或通过网络传输</u>**。
2. **反序列化**：将字节流还原为 Java 对象。

3. **实现方式**：实现 Serializable 接口，通过 ObjectOutputStream 将对象写入输出流（ObjectInputStream 反序列化），完成序列化；使用 **<u>transient 关键词修饰成员变量，可以使该字段不参与序列化</u>**，反序列化后该字段的值为字段类型的默认值（int 0，对象 null）。使用 **serialVersionUID ****<font style="color:#DF2A3F;">序列化版本标识符</font>**，用于确保序列化和反序列化过程中类的**<font style="color:#DF2A3F;">版本一致性</font>**，**<u>显示定义标识符，可以避免因结构变化导致的反序列化失败</u>**。
4. **序列化场景**：Java序列化常用于**对象持久化**(如保存用户登录信息)、**网络传输**(如RMI、RPC调用)、**深拷贝对象**、**缓存存储**(如Redis中存储复杂对象)以及**分布式系统中节点间传递对象**等场景
5. **确保序列化后数据安全**：
    1. 使用 **transient 关键字保护敏感字段**
    2. **自定义 readObject 和 writeObject 方法控制序列化过程**
    3. 对序列化的数据加密

## <font style="color:#DF2A3F;">方法重载和方法重写有什么区别？</font>
**<font style="color:#DF2A3F;">方法重载</font>**：发生在同一个类中，允许多个同名的方法，但是参数列表是不同的，包括参数数量、参数类型不同。<u>在编译期就绑定了所要调用的方法（编译时多态）</u>。

**<font style="color:#DF2A3F;">方法重写</font>**：发生在父类和子类的继承关系中（extends/implements），子类重写父类的某个方法，参数列表和方法名都必须完全相同，从而为该方法提供新的实现。<u>主要用于运行时动态，在运行时进行绑定方法（运行时动态）</u>。

**静态方法无法被重写**：因为重写是运行时多态的体现，依赖于对象实例。**<font style="color:#DF2A3F;">静态方法属于类，不属于实例</font>**，调用的时候是<u>根据引用类型来决定调用哪个方法，不是根据实际对象类型</u>。子类定义同名静态方法只是把父类的方法隐藏了，不是重写。你用父类引用调用，还是调父类的静态方法;用子类引用调用，才调子类的。



## Java 中的参数传递是按值还是引用？
1. **基本数据类型**如 int、char、boolean等:**传递的是值的副本**，也就是基本类型的数值本身。对方法参数的任何修改都不会影响原始变量。
2. **引用数据类型如对象引用:传递的是引用的****<font style="color:#DF2A3F;">副本</font>**，也就是<font style="color:#DF2A3F;">对象引用的内存地址</font>。方法内可以通过引用修改对象的属性，但不能改变引用本身，使其指向另一个对象。
3. **String ：是****<font style="color:#DF2A3F;"> final 常量类，不可变类，无法被继承</font>****，无法修改创建时的内容**，当方法对 String 重新赋值时，其实是创建了一个新的 String 对象，而原始引用仍指向原来的字符。

## 什么是 Java 内部类？有什么作用？
Java内部类就是**定义在另一个类里面的类**，分为**成员内部类（可访问外部类所有成员）、静态内部类（只能访问外部类静态成员）、局部内部类（仅在方法内可见）和匿名内部类（无类名，用于回调/监听）**四种。内部类最大的特点是能直接访问外部类的成员，包括私有成员。

内部类的作用主要有这几点:

1)把逻辑相关的类放在一起，提高**内聚性**，外面用不到的类就不用暴露出去

2)内部类可以直接拿到外部类的成员变量和方法，操作起来很方便

3)对于只在一个地方用的小类，用内部类能减少冗余代码

4)匿名内部类在事件监听、回调这些场景用得非常多，比如Android 的点击事件、Swing 的按钮监听，写起来很简洁

## String、StringBuilder、StringBuffer 有什么区别？
三者都用来处理字符串，核心区别在于**可变性**和**线程安全**。

`**String**` 不可变，底层 char 数组被 final 修饰的，一旦创建无法改变原始值，每次拼接、替换都会生成新的对象。<u>适用于：字符串基本不变，或者少量拼接。</u>

`**StringBuilder**`是可变的，底层使用可扩容的数组存字符，没有加锁机制，是线程不安全的，单线程下性能更好。<u>适用于：单线程下大量拼接操作。</u>

`**StringBuffer**` 是可变的，他的修改数据的方法上都使用了关键字 sychronized 加锁，是线程安全的。<u>适用于：多线程环境下频繁修改字符串。</u>

## 接口和抽象类有什么区别？
**共同点**：

    1. **实例化**:接口和抽象类**<font style="color:#DF2A3F;">都不能直接实例化，只能被实现(接口)或者继承</font>**(抽象类)后才能创建具体的对象
    2. **抽象方法**:接口和抽象类**<font style="color:#DF2A3F;">都可以包含抽象方法。抽象方法没有方法体</font>**，必须在子类或者实现类中实现。

**区别**：

1. **实现方法**:实现接口关键字为implements，继承抽象类的关键字为extends。
2. **设计目的**:**接口**主要用于对类的行为进行约束，实现了某个接口就具有了对应的行为。**抽象类**主要强调代码复用，强调的是所属关系。
3. **继承和实现**:Java 中一个类仅能支持一个类，因为Java 不支持多继承。但是一个类可以实现多个接口，一个接口还可以继承其他更多接口
4. **成员变量**:**<font style="color:#DF2A3F;">接口中只包含常量</font>**，其成员变量隐式被修饰成public static final 类型的，不能被修改并且需要有初始值。但是**<font style="color:#DF2A3F;">抽象类的成员变量默认是default </font>**可以有任何修饰符(private，protected，public)可以在子类中被重新定义或者赋值。**<font style="color:#DF2A3F;">抽象类可以包含实例变量和静态变量</font>**
5. **方法**:
    1. Java 8 之前，接口中的方法显式声明为 public,但是即使不显示声明，它们也是public 的，所以当实现一个接口的时候，来自接口的方法必须被定义为public 。自Java 8 起，可以在接口中定义default 默认方法和 static 静态方。但是Java 9 之后接口可以包括private方法
    2. 抽象类可以包含「抽象方法」和「非抽象方法]。抽象方法没有方法体，必须在子类中实现。非抽象方法有具体实现，可以直接在抽象类中使用或者在子类中重写。被abstract 修饰的方法为抽象方法，不可以被如:private、static、synchronized、native 修饰。

(扩展)从使用方式来看:

1.接口通常暗示"类的类型"或者作为形容词来使用，例如Runnable 和Serializable

2.抽象类通常是类层次结构的一部分，并且是"事物的类型"，例如student 和Instrument

## Java 中 hashCode 、equals、“==”有什么区别？
1.  `==` **<font style="color:#DF2A3F;">比较的是内存地址</font>**，看两个引用是不是指向堆里同一块内存。**<font style="color:#DF2A3F;">对于基本类型，直接比值</font>**。
2. `equals`**<font style="color:#DF2A3F;">比较的是对象内容</font>**，Object 类默认实现就是`==`，但我们通常会重写它来定义"内容相等"的逻辑。比如两个User 对象，id 一样就算相等。
3. `hashCode` **<font style="color:#DF2A3F;">返回一个整数哈希值</font>**，主要给 HashMap、HashSet 这类哈希结构用，**快速定位对象在数组中的槽位**。**哈希码不同，对象肯定不相等;哈希码相同，对象不一定相等**。



## 使用 new String 创建字符串的时候，会创建多少个对象？
**1 个或者 2 个**，取决于字符串常量池是否有这个对象的引用。

1. 如果常量池中**没有**这个对象的引用，那 JVM 会先在堆上创建一个字符串对象放入常量池，然后 new String 的时候堆上又创建一个新对象，共创建了两个对象。
2. 如果常量池中**有**这个对象，new String 的时候只会创建一个对象，常量池直接复用。

核心是 ldc 指令的行为：它会检查常量池是否有指定字符串的引用，**没有就创建并缓存，有就直接返回引用**。



<font style="color:#DF2A3F;">String x = “a”，会创建 0 个或 1 个对象；因为他会直接创建放入常量池，不会再创建新对象放入堆中；但new String 通过关键词 new 总是会创建一个新的 String 对象，</font>**<font style="color:#DF2A3F;">比直接使用字面量要多创建一个</font>****<u><font style="color:#DF2A3F;">堆</font></u>****<font style="color:#DF2A3F;">中 String 对象</font>**<font style="color:#DF2A3F;">。</font>



## Java 的 I/O 流是什么？
Java 的 I/O 流是一套用来读写数据的类库，程序通过他从文件、网络等地方读取数据进来，或者把数据写出去。

I/O 流按数据单位分成两大类：**字节流和字符流**

**字节流**处理 8 位原始字节，适合**<font style="color:#DF2A3F;">处理图片、视频、压缩包</font>**，核心类是 InputStream 和 outputStream。

**字符流**处理 16 位的 Unicode 字符，专门用来**读写****<font style="color:#DF2A3F;background-color:#FBDE28;">文件</font>**，核心类是 Reader 和 Writer。

**字符流不能处理二进制文件**：<u>字符流会把字节按指定编码转换成字符</u>，遇到不符合编码规则的会用替代字符或者直接报错，**<u>图片、视频里的字节序列</u>**<u>大概率不是符合 UTF-8 和 GBK 编码的</u>，所以在读取的时候就会破坏字节。字节流就是原封不动的传输字节，不会有编码问题。

## 什么是 Java 中的迭代器（Iterator）？
Iterator 是**集合框架提供的统一****<u>遍历</u>****接口**。可以安全的遍历和删除元素。

核心方法：（1）hasNext（）判断是否有下一个元素；（2）next（）获取下一个元素；（3）remove（）删除刚刚获取的元素**（安全的删除机制，同步修改计数器）**。

用 Iterator而不是普通for 循环删除?因为在遍历过程中用list.remove()直接删元素会触发fail-fast 机制，抛ConcurrentModificationException。**Iterator 的remove()内部会同步修改计数器**，所以不会报错。



## sleep 和 wait 有什么区别？
最关键的区别就一个:**<u><font style="color:#DF2A3F;">wait()会释放锁，sleep()不会</font></u>**。

+ wait()是Object 类的方法，必须在 synchronized 块里调用，调用后当前线程释放对象锁，进入等待队列，等着别人调 notify()或 notifyAll()把它唤醒。
+ sleep()是Thread 类的静态方法，随便在哪都能调，线程睡指定时间后自己醒。如果当前线程持有锁，睡觉期间锁还攥在手里，别的线程进不来。



## Java 中静态方法和实例方法区别是什么？
**静态方法属于类**，不需要对象就能调用; **实例方法属于对象**，必须先new出来才能用。

1. 静态方法用 static 修饰，通过类名直接调用，比如`Math.sqrt(4)`。它在类加载时就存在了，不依赖任何对象实例。正因为不依赖对象，所以静态方法里不能用this，也不能直接访问实例变量和实例方法。
2. 实例方法不带 static，必须通过对象调用，比如`user.getName()`。它能访问当前对象的实例变量，也能调用静态方法和静态变量，权限比静态方法大。

## 什么是 Java 中的双亲委派模型？
双亲委派模型是**Java类加载机制的一种设计模式**，其核心思想是:当一个类加载器需要加载某个类时，首先将加载请求委派给**<font style="color:#DF2A3F;">父类加载器</font>**去完成，父类加载器还会继续向上委派，直到顶层的**<font style="color:#DF2A3F;">启动类加载器</font>**(BootstrapClassLoader)。**<font style="color:#DF2A3F;">只有当父类加载器无法加载该类时，才会由当前类加载器尝试加载</font>**。这种机制保证了类的层次性和唯一性。

`**目的**`：

+ 一是安全性，防止恶意代码自定义系统核心类(如java.lang.Object)来替换JDK中的原始类，确保核心类库只能由BootstrapClassLoader 加载;
+ 二是保证类的一致性，避免同一个类被不同类加载器重复加载，从而确保JVM中每个类的唯一性。

`**自定义类加载器**`：

可以通过**<font style="color:#DF2A3F;">继承 java.lang.ClassLoader 并重写findClass方法来自定义类加载器</font>**。在findClass 中读取指定类的字节码数据，然后调用 defineClass方法将字节数组转换为Class对象。注意不**要轻易重写IoadClass方法，否则可能破坏双亲委派机制**。**<u>通常只需实现findClass</u>**<u>即可安全地扩展类加载逻辑</u>。



## Java 中的泛型？
1. `**泛型定义**`：
+ 什么是泛型：核心是**「****<font style="color:#DF2A3F;">参数化类型，保证类型转换安全</font>****」**，允许在定义类、接口、方法时，不指定具体类型，而是将类型作为一个参数传递，在使用时再确定具体类型（以 Java 为例，典型如List<String>）。
+ **核心作用**：① 编译期类型安全，避免运行时ClassCastException；② 消除冗余的强制类型转换，简化代码；③ 实现代码复用，一套泛型代码可适配多种数据类型（如ArrayList可存储字符串、整数等）。
+ **<font style="color:rgb(51, 51, 51);">类型擦除</font>**<font style="color:rgb(51, 51, 51);">‌：Java 泛型仅在编译期有效，运行时泛型信息会被擦除（如 </font>`<font style="color:rgb(51, 51, 51);">List<String></font>`<font style="color:rgb(51, 51, 51);"> 变为原始类型 </font>`<font style="color:rgb(51, 51, 51);">List</font>`<font style="color:rgb(51, 51, 51);">），因此‌</font>**<font style="color:rgb(51, 51, 51);">无法通过反射以外的方式在运行时获取泛型实际类型</font>**<font style="color:rgb(51, 51, 51);">‌‌</font>
2. `**泛型使用方式**`：
+ ① 泛型类 / 泛型接口：定义类 / 接口时声明类型参数（如public class ArrayList<E>、public interface Comparable<T>）；
+ ② 泛型方法：方法声明时独立定义类型参数（可用于静态方法，与类泛型无关，如public <T> T getFirst(List<T> list)）；
3. `**泛型应用场景**`：
+ <font style="color:#DF2A3F;">集合框架操作</font>：如List<User> userList、Map<Long, Order> orderMap，存储业务对象并保证类型安全；
+ 自定义通用组件：如通用分页结果        类PageResult<T>，适配用户、订单等各类数据的分页返回；
+ <font style="color:#DF2A3F;">通用 CRUD 接口</font>：如BaseMapper<T>，封装单表增删改查逻辑，子类只需指定实体类型即可复用（如UserMapper extends BaseMapper<User>）；
+ 工具类封装：如通用对象拷贝方法copyProperties(T source, U target)、JSON 序列化 / 反序列化工具（如 Jackson 处理T类型对象）。

## ❤ sleep、wait、yield、join
`**sleep**`：属于 <font style="color:#DF2A3F;">Thread</font>，可以在方法内任意位置使用；会释放 CPU 资源，<u>但不会释放锁</u>，**<font style="color:#DF2A3F;">不考虑其他线程的优先级</font>**，等设定的时间到了以后会自动唤醒；

`**wait**`：属于 <font style="color:#DF2A3F;">object</font>，只能用于同步块或同步方法中；<u>会释放锁</u>，需要手动 notify 唤醒以后去竞争锁；

`**yield**`：属于 <font style="color:#DF2A3F;">Thread</font>，<u>不会释放锁</u>，考虑线程优先级，**<font style="color:#DF2A3F;">会让和自身相同优先级或优先级更高的线程执行</font>**；可能随时唤醒执行任务；

`**join**`：属于 <font style="color:#DF2A3F;">Thread</font>，<u>会释放锁</u>；**<font style="color:#DF2A3F;">调用 join 的线程会优先使用 CPU 执行任务</font>**，其他线程需等待 join 线程执行完毕后才能继续 z还执行。

**<font style="color:rgb(51, 51, 51);">（1）sleep()与wait()的区别？</font>**

1. <font style="color:rgb(51, 51, 51);">sleep() 是 Thread 类的静态本地方法；wait() 是Object类的成员本地方法；</font>
2. <font style="color:rgb(51, 51, 51);">JDK1.8 sleep() wait() 均需要捕获 InterruptedException 异常；</font>
3. <font style="color:rgb(51, 51, 51);">sleep() 方法可以在任何地方使用；wait() 方法则只能在同步方法或同步代码块中使用；</font>
4. <font style="color:rgb(51, 51, 51);">sleep() 会休眠当前线程指定时间，释放 CPU 资源，不释放对象锁，休眠时间到自动苏醒继续执行；wait() 方法放弃持有的对象锁，进入等待队列，当该对象被调用 notify() / notifyAll() 方法后才有机会竞争获取对象锁，进入运行状态。</font>

**<font style="color:rgb(51, 51, 51);">（2）sleep()与yield()的区别？</font>**

1. <font style="color:rgb(51, 51, 51);">sleep() 方法给其他线程运行机会时不考虑线程的优先级；yield() 方法只会给相同优先级或更高优先级的线程运行的机会；</font>
2. <font style="color:rgb(51, 51, 51);">sleep() 方法声明抛出 InterruptedException；yield() 方法没有声明抛出异常；</font>
3. <font style="color:rgb(51, 51, 51);">线程执行 sleep() 方法后进入超时等待状态；线程执行 yield() 方法转入就绪状态，可能马上又得得到执行；</font>
4. <font style="color:rgb(51, 51, 51);">sleep() 方法需要指定时间参数；yield() 方法出让 CPU 的执行权时间由 JVM 控制。</font>

**<font style="color:rgb(51, 51, 51);">（3）sleep()与join()的区别？</font>**

1. <font style="color:rgb(51, 51, 51);">JDK1.8 sleep() join() 均需要捕获 InterruptedException 异常；</font>
2. <font style="color:rgb(51, 51, 51);">sleep()是Thread的静态本地方法，join()是Thread的普通方法；</font>
3. <font style="color:rgb(51, 51, 51);">sleep()不会释放锁资源，join()底层是wait方法，会释放锁。</font>
