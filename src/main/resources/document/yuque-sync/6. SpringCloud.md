##  什么是微服务？
微服务是一种软件架构风格，它将**一个**复杂的应用程序**拆分为多个**职责单一的小型服务，每个服务独立运行、独立部署，并通过轻量级通信机制(如HTTP或RPC、**RabbitMQ 异步通信**)进行交互。其核心思想是遵循**单一职责原则**’，实现服务的高内聚和低耦合。

优点：

1)独立部署，降低发布风险;

2)技术栈多样性，不同服务可选用最适合的技术语言或框架;

3)灵活扩展，可根据负载情况对特定服务进行横向扩展;

4)**容错性强，单个服务故障不会导致整个系统崩溃。**

## SpringCloud 有哪些核心组件？
SpringCloud 的核心组件主要包括:

1. **服务注册与发现**(如Eureka、Nacos)
    1. `**服务注册**`：服务启动时，将自己的**元信息(如服务名、IP地址、端口号、健康状态等)**注册到注册中心，注册中心保存这些信息并用于后续的服务发现。
    2. `**服务发现**`：服务消费者向注册中心**查询所需服务的实例例表**，注册中心返回可用的服务实例信息，消费者**根据****负载均衡策略****选择一个实例进行调用**。
2. **负载均衡**(如Ribbon、SpringCloud LoadBalancer)
3. **配置中心**(如 Spring Cloud Config、Nacos)：实现配置的**集中管理**、支持配置的**动态刷新**、减少服务重启次数、提高系统可用性，并支持**多环境配置**(如开发、测试、生产)和权限控制，保障**配置安全**
4. **服务调用**(如OpenFeign)：整合了Spring Boot 和 Spring Cloud生态，支持**自动配置**、**负载均衡**(如与 Ribbon 集成)、**服务发现**、Hystrix**熔断**等特性,
5. **熔断与限流**(如Hystrix、Sentinel、Resilience4j)
6. **网关**(如Zuul、Spring Cloud Gateway)：负责**请求路由**、**身份认证**、**限流熔断**、**日志记录**等功能。它可以将外部请求转发到对应的微服务，同时屏蔽内部服务的复杂性，提升安全性和可管理性。
7. **消息驱动**(如Spring Cloud Stream)
8. **链路追踪**(如 Sleuth + Zipkin)
9. **监控管理**(如 Spring Boot Admin)。

这些组件共同解决微服务中的服务治理、配置管理、流量控制、监控等问题

## Nacos 中的 Namespace？
Namespace是Nacos提供的一个用于逻辑隔离的最高级别单位，主要用于**将不同的服务和配置进行分组隔离**。不同Namespace 之间的资源(如服务实例、配置信息)完全独立，互不影响。常见用途包括环境隔离(如开发、测试、生产)、多租户管理和项目隔离。

##  什么情况下需要使用分布式事务？
当业务操作涉及**多个数据库或跨服务**时，例如订单服务创建订单和库存服务扣减库存，它们属于不同的数据源。本地事务只能保证单个数据库的原子性，无法保证跨服务的一致性。此时如果不使用分布式事务，可能出现订单创建成功但库存未扣减，或反之的情况。因此，当需要多个操作要么全部成功，要么全部回滚"时，就必须使用分布式事务来保证整体的数据一致性。

## 分布式和微服务的区别是？
1. `**分布式**`**：**关注的是任务如何在**多台机器上协作执行**，重点在于基础设施和资源分配;
2. `**微服务**`**：**是一种软件架构风格，关注的是**将业务功能拆分为多个独立、松耦合的服务单元**。简单说:分布式是干活的方式，微服务是组织的架构。

## 什么是 Seate？
1. Seata是阿里开源的分布式事务解决方案，专门解决微服务场景下**跨服务、跨数据库的数据一致性问题**。分布式事务的难点在于，一个业务操作可能涉及多个服务、多个数据库，每个服务本地事务能保证ACID，但整体业务的原子性没人管。
2. **三大核心组件**：
    1. `**事务协调器**`（TC）：负责**管理全局事务的生命周期，记录全局事务和分支事务的状态，并协调全局事务的提交与回滚**。它是Seata的中心控制器，保证各分支事务在全局事务中的一致性，并在异常时通知RM执行回滚操作。
    2. `**事务管理器**`（TM）：负责**定义全局事务的边界**，通过@GlobalTransactional注解或API标记全局事务的开始、提交或回滚。它向TC发起创建全局事务的请求，并在业务执行完成后通知TC提交或回滚全局事务。
    3. `**资源管理器**`（RM）：负责**管理本地数据库资源，处理分支事务的注册、提交和回滚**。它在执行数据库操作时生成undo_log快照（存储AT 模式下**数据修改前的快照信息**，包括修改的 SQL类型、前后镜像等。当全局事务需要回滚时，Seata 会读取该表中的快照，将数据恢复到事务执行前的状态，从而**实现自动回滚**。），向TC注册分支事务，并根据TC的指令执行本地提交或基于快照的数据回滚。
3. **全局事务执行流程**：首先TM向TC请求创建全局事务，TC生成XID并返回;接着业务执行时RM注册分支事务并向TC上报;然后本地事务提交并记录undo_log;最后TM通知TC提最后交或回滚，TC协调所有RM完成第二阶段操作，TC更新全局事务状态并清理日志。

## Seata 是如何实现分布式事务的？
Seata的**AT 模式是一种自动化的2PC方案**。它通过代理数据源，在本地事务执行时**自动生成前后镜像**并记录到UndoLog中。全局事务提交时直接提交;若回滚，则根据UndoLog自动还原数据。开发者无需编写额外的回滚逻辑，对业务几乎无侵入。Seata 还支持TCC、Saga、XA 模式，但在SpringCloud 微服务架构中，AT 模式最为常用。

---
## 分布式事务的强一致性和最终一致性有何区别？
1. 强一致性(如2PC、TCC)要求事务**执行过程中所有节点始终保持一致，****任何时刻都满足ACID特性**，适合对数据一致性要求极高的场景，但性能较低。
2. 最终一致性(如本地消息表、事务消息)允许中间状态短暂不一致，只要求经过**一段时间后系统能自动收敛到一致状态**，具有更高的并发能力和吞吐量，适用于电商、社交等高并发互联网场景，牺牲一点实时性换取性能提升。

## 什么是负载均衡？
负载均衡是一种**将网络请求或流量分发到多台服务器或服务实例上**的技术,目的是提高系统的高可用性、性能和可扩展性，避免单个服务器因负载过高而成为瓶颈或发生故障。

常见策略：

1. **轮询**(Round Robin)：按**照顺序将请求****依次分配****给后端服务器**，适用于后端服务器性能相近的场景。其优点是实现简单、均衡性好，但缺点是在服务器性能差异较大时，可能导致负载不均。
2. **加权轮询**(Weighted Round Robin)：为每台服务器**设置权重**，**权重越高****的服务器被****分配的请求越多**。这种算法可以根据服务器的处理能力合理分配负载，提升整体系统吞吐量，适合服务器性能不均的环境。
3. **随机算法**：随机算法通过**随机选择**后端服务器来分发请求，每个服务器被选中的概率相同。该方法实现简单，但在服务器性能不一致时容易造成负载不均。
4. **最少连接**(Least Connections)：**将请求分配给当前****连接数最少****的服务器**，能够动态反映服务器的负载情况，特别适用于请求处理时间不一或服务器性能不同的场景，有效避免某台服务器过载（**适合处理长链接或者耗时请求）**
5. IP哈希(IP Hash)：哈希算法根据请求的某一特征(如客户端IP、URL等)计算哈希值，并映射到特定的后端服务器，确保相同特征的请求总是转发到同一台服务器，常用于需要会话保持的场景，如Redis集群。

## 什么是 Feign？
Feign是一个声明式的Web服务客户端，它允许开发者**通过****定义接口****并****使用注解****的方式来描述HTTP请求**，而不需要手动编写复杂的HTTP客户端代码。Feign在运行时根据接口定义和注解信息动态生成请求，**简化了服务间调用的开发过程**。它是SpringCloudNetflix的组件之一，能够与服务发现、负载均衡等能力集成，使微服务之间的通信更加简单和直观。

`**工作机制**`：Feign 在运行时**通过动态代理机制**，对接口进行代理，根据**接口上的注解**(如@GetMapping、@PostMapping)和**参数注解**(如@PathVariable、@RequestParam)**生成对应的 HTTP 请求**。然后**利用底层的客户端**(如HttpURLConnection、OkHttp)发送请求，并将响应结果**反序列化为Java 对象返回**给调用方。

## Feign 实现负载均衡的关键步骤？
1. 定义Feign接口;
2. 集成注册中心(如Nacos);

## 什么是熔断器？为什么需要用熔断器？（关闭、打开、半开状态）
用于**防止**微服务架构中的**雪崩效应**。它通过熔断、降级、隔离和监控等机制，提升系统的稳定性和容错能力。当某个服务出现故障时，能够快速失败并提供降级响应，避免请求堆积和资源耗尽。

`**核心功能**`：

1. **熔断机制**一一当下游服务失败率达到阈值时自动切断请求
2. **服务降级**一一在服务异常时返回预设的默认响应;
3. **资源隔离**一一通过线程池或信号量隔离不同服务的调用，防止故障扩散。

## 什么是服务雪崩？
`**服务雪崩**`：是指在微服务架构或分布式系统中，由于**某个服务不可用**或性能下降，**导致依赖它的其他服务也出现连锁故障**，最终使整个系统或大部分服务不可用的现象。

`**防范措施**`：

1. 熔断器：------------
2. 服务降级：在某个服务不可用时提供备用方案（超时、调用失败、系统负载过高、下游依赖服务不可用），**返回默认值或简化结果**。例如库存服务故障时，可**返回缓存的库存数据或提示库存信息暂时不可用**’，保证用户仍能继续下单等操作。
3. 限流与隔离：
    1. 限流通过令牌桶、漏桶等算法**控制请求速率**，防止突发流量压垮服务;
    2. 隔离则通过**线程池或信号量**等方式**限制不同服务间的资源争用**，确保一个服务的故障不会影响其他服务。

`**服务降级与熔断的区别**`：**服务降级**主要是应对系统压力或者故障的调整策略，**涉及****关闭非核心功能**，而熔断是当某个服务**连续调用失败以后，自动暂停对该服务的请求**，属于降级的一种具体实现方式。**熔断通常是自动触发的，降级可以是自动或人工决策**。

---
## 什么是服务限流？
服务限流是一种流量控制策略，通过**限制系统在****单位时间内处理的请求数量(如QPS、并发数****等)**，来保护服务的稳定性，防止因流量过大导致系统性能下降或资源耗尽。它**属于服务降级的一种形式**，目的是确保核心功能在高负载下仍能正常运行。

## Sentinel 如何实现限流？
`**核心思路**`：**定义资源 -> 配置规则 -> 流量统计 -> 限流判断**

Sentinel通过**定义资源、设置限流规则和执行限流算法**来实现流量控制。当请求进入系统时，Sentinel 首先对请求进行统计(如QPS、线程数)，然后根据配置的限流规则判断是否超过阈值。若超出，则触发限流措施，如直接拒绝、排队等待或降级处理。

`**核心组件包括**`：SlotChain(处理拦截逻辑)、Flow Slot(执行流控检查)和Statistic Node(记录统计信息)，结合固定窗口、滑动窗口、令牌桶或漏桶等算法完成精确的流量控制。

`**限流规则**`： Sentinel支持多种限流模式(如**直接、关联（某个 A 达到请求阈值，限制另一个 B 的访问）、链路（基于调用链路来源进行流量控制）**)和策略(**QPS、线程数**)，提供实时监控和动态规则配置，并具备**可视化控制台**，适合微服务架构下的精细化流量管理。

`**限流算法**`：

    1. 滑动窗口：统计实时 QPS（每秒请求次数）
    2. 令牌桶：支持**突发流量处理**并控制平均速率（**平滑流量控制**）

## 什么是服务网格？
服务网格是一个专门用于**处理服务间通信**的基础设施层，它通过在每个微服务旁边部署一个Sidecar代理，拦截服务之间的网络流量,实现流量管理、故障恢复、服务发现等功能。其核心思想是**将通信逻辑从应用代码中剥离出来**，提升系统的可观测性、可管理性和可维护性。

## 什么是微服务网关？为什么需要微服务网关？
微服务网关是一个用于**代理客户端请求并将其****分发到后端微服务****的服务器**。它作为系统的统一入口，接收所有客户端请求，**根据配置的路由规则将请求转发到相应的微服务**，并可在转发过程中执行**鉴权、限流、缓存、协议转换**等操作，实现对请求的集中管理和控制。

功能：

1. 统一管理服务的调用入口与出口，简化服务间调用
2. 提高系统性能（如通过缓存和协议转换）
3. 降低配置复杂度：统一处理跨域、鉴权、限流等公共逻辑
4. 实现安全鉴权、负载均衡、流量控制等服务保护机制，提升系统的稳定性与安全性。
5. 日志记录

## SpringCloud Gateway
`**核心功能**`：

1. 路由转发
2. 过滤机制：请求前后执行预处理和后处理逻辑，如身份认证、日志记录、限流
3. 响应式编程：基于WebFlux和Reactor 实现高性能异步非阻塞处理；
4. 与 SpringCloud 生态良好集成，支持服务发现、配置中心等
5. 统一管理流量入口

`**三大组件**`：

1. Route（路由）：定义了**请求的转发目标**
2. Predicate（断言）：决定**请求是否匹配该路由**，例如通过路径、请求头、方法等条件判断；
3. Filter（过滤器）：用于在请求前后进行拦截和修改，实现如**添加****头信息、权限校验、限流****等功能**。

## 什么是 API 网关？作用是什么？
API网关是位于客户端与后端服务之间的一层，作为所有**客户端请求的统一入口**，负责将请求路由到正确的后端服务，并提供**认证、限流、负载均衡、缓存、日志记录**等能力。它屏蔽了后端微服务的复杂性，使客户端无需关心具体服务的部署细节和接口结构。

`**核心作用**`：

1. **简化客户端调用**，提供**统一入口和请求聚合**；
2. **增强系统安全性**，实现**统一的身份认证、授权**和内部结构隐藏；
3. 进行**流量管理与优化**，如**负载均衡、限流熔断、缓存**等；
4. 支持**协议转换和响应加工**，提升系统兼容性和灵活性。
