## @Component和@Configuration区别？
| 特性 | `@Component` | `@Configuration` |
| --- | --- | --- |
| **本质** | **通用组件注解** | **特殊配置类注解** |
| **代理方式** | 不创建代理 | 创建CGLIB代理 |
| **Bean方法调用** | 普通方法调用 | 被拦截，从Spring容器获取 |
| **主要用途** | **标识普通组件类** | 定义配置和Bean组装逻辑 |


**总结**：**需要写**`**@Bean**`**方法就用**`**@Configuration**`**，否则用**`**@Component**`

调用方式：（**@Component 使用 类名 + 小写类名，可以使用该类下所有方法；@Configuration 使用 @Bean注解定义的方法类型和方法名进行字段注入，只能使用定义 Bean 的方法；两者使用范围不一样：****一个是可以使用类中所有方法****，一个是只能****使用具体定义 @Bean注解的方法**）

**@Component：**

```java
@Component
public class OrderService {

    public String xxx(){
        return "xxx";
    }

    public String aaa(){
        return "aaa";
    }
}

// 使用方式，使用的是最大的类名，这样可以调用这个类中所有方法
@Autowried
private OrderService orderService;
orderService.xxx();
orderService.aaa();
```

```java
@Component
public class OrderService {

    // 方式1：构造器注入（推荐）
    private final UserService userService;
    private final EmailService emailService;

    @Autowired
    public OrderService(UserService userService, EmailService emailService) {
        this.userService = userService;
        this.emailService = emailService;
    }

    // 方式2：Setter注入
    @Autowired
    public void setSmsService(SmsService smsService) {
        this.smsService = smsService;
    }

    // 方式3：字段注入（不推荐，但常见）
    @Autowired
    private PaymentService paymentService;
}
```

**@Configuration：**

```java
@Configuration
public class DataSourceConfig {

    @Bean
    public DataSource dataSource() {
        return new HikariDataSource();
    }
}

// 同样可以注入使用
@Service
public class UserService {
    // 使用方式
    @Autowired
    private DataSource dataSource;  // 注入的是@Bean定义的对象
}
```

## Spring 的启动过程？
Spring 启动的**核心就是创建并初始化 IOC 容器**，拆分阶段：

1. **准备阶段（prepareRefresh）**：初始化环境，设置启动时间，验证必要属性
2. **加载 bean 定义（obtainFreshBeanFactory）**：创建 `BeanFactory`；解析配置类，扫描 `@Component` 等注解；将类封装成 `BeanDefinition` 注册到容器
3. **后置处理（invokeBeanFactoryPostProcessors）**：****修改 Bean 定义；解析 `${}` 占位符，处理自动配置
4. **注册拦截器（registerBeanPostProcessors）**：注册 BeanPostProcessor，用于后续拦截 Bean 创建
5. **实例化 Bean（finishBeanFactoryInitialization）**：
    1. 核心阶段：创建所有单例 Bean
    2. 执行顺序：
        1. 构造函数实例化
        2. 依赖注入（`@Autowired`）
        3. `Aware` 接口回调
        4. `BeanPostProcessor.before`
        5. 初始化（`@PostConstruct` → `InitializingBean` → `init-method`）
        6. `BeanPostProcessor.after`（**AOP 代理在此创建**）
        7. 放入单例池

最后 `finishRefresh()` 发布启动完成事件。

与 SpringBoot 差异："Spring Boot 在 `refresh()` 前增加了：**推断应用类型 → 加载配置文件 → 自动配置 → 创建内嵌容器**，最终还是会调用标准的 `refresh()` 方法。"

## Spring 由哪些重要的模块组成？
Spring主要分为五个核心模块:

1. **核心容器**，包括Core、Beans、Context 和SpEL，提供**loC（控制反装）和DI（依赖注入）**功能；
    1. 其中，**core 和 beans **模块提供 IOC 和 DI 功能，实现 Bean 的创建和管理；
    2. **context **在 core 基础上扩展了国际化、事务传播、资源加载等功能
    3. **spel **是 Spring 表达语言，支持实时查询和操作图。
2. **AOP模块**持面向切面编程，用于日志、事务等横切关注点；主要用于 Spring 容器管理的 bean，支持方法级别的拦截；不同于** AspectJ，它是更强大的 AOP 框架，支持字段、构造器、方法等多种连接点，功能更全面复杂**。
3. **数据库交互模块**，包含JDBC、Transaction和ORM支持，简化数据库操作和事务管理；通过 JDBC 模块提供的 JdbcTemplate 工具类，封装了数据库链接、异常处理和释放资源等重复场景，使得开发者只需关注 SQL 逻辑。
4. **Web层模块**，如SpringMVC（基于 Servlet 的传统 web 框架，采用同步阻塞 I/O，适合常规的请求-响应模型）和WebFlux（基于 Reactor 的响应式框架，采用异步非阻塞编程，适用于高并发、低延迟场景），用于构建Web应用
5. **Test模块**，集成测试框架如JUnit和TestNG，支持在测试中加载Spring容器、加载配置文件和注解配置，自动注入 bean，方便测试服务层和数据访问层等组件的功能。
6. **支持事务@Transactional**

ApplicationContext 作用：

ApplicationContext 是 Spring 的核心接口，代表Spring 容器，负责管理 Bean 的生命周期、依赖注入、配置元数据加载等。它在 BeanFactory基础上增加了更多企业级功能，如事件发布、国际化支持、资源访问、AOP集成等，是实际开发中最常用的容器实现。

## Spring 中的 DI 和 IOC 是什么？
**IoC（控制反转）**：是指对象的**创建和依赖关系**都由 Spring 容器进行管理，而不是由程序代码去控制

+ **流程**：
+ （1）加载配置（**定义对象和他们的依赖关系**），读取 XML、注解、或 java 配置，解析为 beanDefinition；
+ （2）注册 Bean 定义，将 BeanDifinition 注册到 BeanDefinitionRegistry；
+ （3）实例化 bean，**使用反射根据类名创建对象实例**
+ （4）依赖注入，通过构造器、setter 或字段注入方式，利用反射填充依赖
+ （5）初始化和管理，执行初始化方法，并交由应用管理。

**DI（依赖注入**）：是 Ioc 的具体实现，指在容器创建时，**自动将其所依赖的对象****通过构造函数、setter 等方法注入进去，不需要手动 new **，实现松耦合、提供灵活性和可测试性；

## 为什么 Spring 循环依赖需要三级缓存？
1. **一级缓存**(singletonObjects)存放完全**初始化完成的单例 Bean 实例**，是最终可用的 Bean 对象;
2. **二级缓存**(earlySingletonObjects)存放早期暴露的 Bean 实例(**可能是原始对象或代理对象**)，用于解决循环依赖，它的作用是**存储的是三级缓存工厂的产出物**。;
3. **三级缓存**(singletonFactories)**存放****ObjectFactory****工厂对象，用来延迟生成早期引用**，特别是支持AOP代理的按需创建。当 Bean实例化完成之后，先将这个工厂放入三级缓存，而不立即生成代理。如果后续出现循环依赖，其他 Bean需要引用该 Bean，则通过调用工厂的getObject()方法来获取早期引用一一此时才会判断是否需要创建代理对象;如果没有循环依赖，这个工厂就不会被调用，代理将在初始化完成后正常创建。（解决循环依赖、不破坏正常的 bean 生命周期

##  什么是 Spring 的 Bean？
Bean 是 **Spring 容器实例化、组装和管理的 Java 对象**，他是 Spring 应用程序的核心组成部位，其生命周期（包括创建、初始化、使用和销毁）完全由 Spring 所管理。

Bean 的生命周期四个阶段（**不同作用域，Spring 管理的周期不同：默认 singleton 全周期；prototype 只负责创建和初始化，后续需要手动管理**）：

1. **实例化**——Spring 根据配置或者注解创建 Bean 实例
2. **依赖注入**——容器将 Bean 所需的依赖通过构造器、Setter、字段注入的方式进行依赖注入
3. **初始化**——依赖注入完成以后，若 Bean 实现了 IntilizingBean 方法或者使用@PostConstruct 注解，则执行初始化方法
4. **销毁**——当容器关闭时，若 Bean 实现了 DisposableBean 接口或者使用@PreDestroy 注解，会对 bean 对象进行销毁。

`**Bean 的作用域**`：

1. **通用作用域**：
    1. singleton：默认作用域，每个 Spring 容器只有一个实例 Bean
    2. prototype：每次请求都会创建一个新的 Bean 实例，在这个作用域下 Spring 只负责 bean 的创建和实例化，不负责销毁，需要手动管理
2. **Web 专用作用域**：
    1. request：每个 HTTP 请求创建一个 Bean 实例，请求结束后销毁 Bean
    2. session：每个 HTTP Session 创建一个 Bean 实例，Session 失效时销毁 Bean
    3. application：每个 ServletContext 生命周期内一个 Bean 实例
    4. websocket：每个 WebSocket 会话创建一个 Bean 实例

## 什么是 AOP？
`**概念**`： AOP(Aspect-Oriented Programming，面向切面编程)是一种编程范式，用于将横切关注点(如日志、事务、安全等)与核心业务逻辑分离。它通过定义切面，在不修改原有代码的情况下，将通用功能动态织入（**JDK 动态代理，如果目标类没有实现接口，则会使用CGLIB动态代理(基于子类)**）到多个方法执行的特定位置，实现代码解耦和复用。

`**组成部分**`：** ****切面(Aspect，自定义的切面逻辑)、连接点(Join Point，切面逻辑执行的位置)、通知(Advice，将切面在连接点处执行的动作)、切入点(Pointcut，定义在哪些位置切入  )和织入(Weaving)****。**切面封装横切逻辑;连接点是程序执行的特定位置;通知是切面在连接点执行的动作;切入点定义匹配哪些连接点（方法名、类名、包路径等）;织入是将切面应用到目标对象的过程。

`**通知类型**`：

1. 前置通知(@Before)在方法执行前运行;
2. 后置通知(@After)无论方法是否成功都执行;
3. 返回通知(@AfterReturning)在方法成功返回后执行;
4. 异常通知(@AfterThrowing)在方法抛出异常后执行;
5. **环绕通知(@Around)**最强大，可以控制方法的执行前后逻辑，甚至决定是否执行原方法。

## JDK 的动态代理如何工作？
JDK 动态代理**基于反射机制**，通过 Proxy类和 InvocationHandler接口实现。在运行时，Proxy.newProxyInstance()方法会根据目标类的类加载器和实现的接口动态生成一个代理类实例，所有方法调用都会被转发到InvocationHandler 的invoke()方法中，从而可以在**方法前后添加增强逻辑**。

静态代理：

**静态代理则在编译期或类加载期由工具修改字节码完成织入(如AspectJ)**，性能更高但需要额外编译步骤。

动态代理：

**在运行时由 JVM 生成代理类。**

## Spring 拦截器链的实现
Spring拦截链本质上就是**把一系列拦截器串成一个链条，请求或方法调用依次经过每个拦截器处理**。这套机制用来实现**日志记录、权限校验、事务管理**。这类横切关注点，不用把这些逻辑塞到业务代码里。

三种拦截方式：

1. `Handlerlnterceptor`(MVC拦截器)，用于拦截HTTP请求的**预处理**和**后处理;**
    1. preHandle在请求到达控制器之前执行，返回false可中断请求;
    2. postHandle在控制器方法执行之后、视图渲染之前行；
    3. afterCompletion在请求完成、视图渲染之后执行结束后执行，通常用于**资源清理**。
2. `Filter`(过滤器)，基于Servlet API，用于**请求的初步筛选如编码、安全、跨域**等;
3. `AOP` 拦截链(切面)，**实现方法级别的拦截**，**通过@Before、@After等注解进行****逻辑切入**。

❤`**区别**`：

1. **Handlerlnterceptor** 是 SpringMVC 的拦截器，**仅对 DispatchServlet 处理的请求生效**，粒度更细；
2. **Filter** 是 Servlet 规范的一部分，作用于整个 Web 请求生命周期，**能够处理所有进入应用的请求（包括静态资源）**。

**HandlerInterceptor 和 Filter 应用场景：**

**HandlerInterceptor：**适用于和业务逻辑有关的，如登录校验、权限检查，需要用到 service 层的能力

**Filter：**适用于和 HTTP 协议本身相关的，如字符编码、跨域、请求日志，跟具体业务无关的场景

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    // 1.先实现HandlerInterception接口，重写preHandler等方法
    // 2.创建一个类，实现WebMvcConfigurer接口，重写addInterceptors方法，将刚刚创建的类的实例添加进去
    @Autowired
    private AuthInterceptor authInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(authInterceptor)
            .addPathPatterns("/api/**")           // 拦截 /api 开头的请求
            .excludePathPatterns("/api/login");   // 排除登录接口
    }

    @Bean
    public FilterRegistrationBean corsFilter() {
        FilterRegistrationBean bean = new FilterRegistrationBean<>();
        bean.setFilter(new CorsFilter());
        bean.setOrder(Ordered.HIGHEST_PRECEDENCE);  // 跨域要最先处理
        bean.addUrlPatterns("/*");
        return bean;
    }
}

```

## SpringMVC 的理解
Spring MVC是Spring框架中用于 Web 应用的开发，核心思想是 MVC 分层：**Model（负责数据）、View（用于视图展示）、Controller（负责接收请求和协调）**。

`**核心组件**`：**DispatcherServlet，它是前端控制器，负责接收所有HTTP 请求，并将请求分发给对应的处理器(Controller)来处理业务逻辑，并协调视图解析与渲染，返回最终的响应结果**。其他核心组件包括：HandlerMapping（处理器映射器）、HandlerAdapter（处理器适配器）HandlerInterceptor（拦截器）、Controller（控制器）、ModelAndView（模型和视图）、ViewResolver（视图解析器）。

## Spring 事务会在哪些情况下失效？
Spring事务失效通常发生**在使用了@Transactiona注解但末正确配置或使用的情况下**，主要原因包括

1. rollbackFor未正确设置：注解默认只对 RuntimeException 和 Error 回滚，方法抛出的是 checked 异常（如 IOException），则不会回滚，需要显示配置 rollbackFor = Exception.class 才能覆盖所有异常
2. **异常被catch未抛出**：没有抛出，Spring 事务管理器无法感知，从而无法回滚
3. **同类中方法直接调用导致代理失效（Spring 的事务是通过代理的）**：类内部方法直接调用属于 this 调用，不会触发代理，从而不生效。
4. **注解用在非pubic方法上、用在 final 或 static：****@Transaction只用于public方法上，final和static 不能被子类重写，动态代理无法生成增强的子类**
5. 事务传播机制配置错误
6. 多线程环境下事务不同步：因为Spring事务依赖ThreadLocal存储事务上下文，每个线程有独立的上下文空间，子线程无法继承父线程的事务状态，导致事务无法跨线程传播和控制。
7. **数据库引擎不支持事务**(如MyISAM)

## SpringMVC 中如何处理异常？
1. 使用 @ExceptionHandler 注解进行局部异常处理，通常定义在控制器中
2. 使用@ControllerAdvice 或者@RestControllerAdvice （用于RESTful 服务，返回 JSON 或 XML 格式的响应）实现全局异常处理，作用于所有控制器

@ExceptionHandler（value = ），value 用于处理哪些异常（捕获哪些异常），都要捕获选择 Exception，它是所有异常的父类。

```java
// value = Exception.class 用于捕获所有类型的异常，控制器出现异常时，都会走这个方法
// 也可以写 value = IOException.class，NullPointerException.class 这样可以捕获特定的异常

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(value = Exception.class)
    public ResponseEntity handleException(Exception e) {
        // 日志记录
        e.printStackTrace();
        // 自定义响应体
        return ResponseEntity.status(500).body("发生错误：" + e.getMessage());
    }
}
```

3. 自定义拦截器：首先创建实现**Handlerinterceptor**接口，并重写其三个方法;然后通过实现 **WebMvcConfigurer**接口，在 addinterceptors 方法中使用InterceptorRegistry注册该拦截器，并配置拦截路径和排除路径

## 什么是 Restful 风格的接口？
RESTful 风格的接口是一种**基于资源的 Web APl设计风格**，遵循REST (Representational State Transfer，**表述性状态转移**)架构原则。它使用标准的 HTTP方法(如GET、POST、PUT、DELETE)对资源进行操作，通过URI定位资源，强调无状态通信，并使用统一的HTTP状态码返回结果。**核心是用URL表示资源，用HTTP动词表示操作**。

Restful 中的幂等性：**put、delete、get 都是幂等的**，**post 每次都会创建一个新的资源，是非幂等的**。

## @RestController 和 @ controller 有什么区别？
`**@Controller**`用于传统的Spring MVC控制器，通常**返回视图名称**，需配合@ResponseBody才能返回 JSON数据;

`**@RestController****（将方法返回值传回前端 HTTP 中）**`是**@Controller和@ResponseBody**的组合，所有处理方法**默认将返回值直接写入HTTP响应体**，适用于构建RESTfuI风格的APl，无需额外添加@ResponseBody注解

`**@RequestBody****（将前端传入参数从 JSON 转换为 JAVA 对象）**`，用于方法中传入的参数列表，将**前端传入的表单数据，转换为 JAVA 对象**，映射到指定字段上。
